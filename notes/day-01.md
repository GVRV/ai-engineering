### 3Blue1Brown: [But what is a neural network? | Deep learning chapter 1](https://www.youtube.com/watch?v=aircAruvnKk)

- What is a neuron here, really? (Hint: a number, not a brain cell.)

Answer: Each neuron is a function that generates the weighted sum from a bunch of inputs, adds its own activation bias and computes an output number that might signify whether this neuron has been "activated" or not given the inputs.

- What do weights and biases do?

Answer: Weights and biases are "knobs" in the neural network that can be tweaked to get the network to learn/perform the desired task. The weight is how much preference is given to one of the inputs coming in and the bias is the activation bias in the neuron.

- Why stack layers instead of one giant lookup table?

Answer: This wasn't explicitly mentioned in the video but I can take a dig at it. Given the complexity of recognizing digits and the possible inputs that exist, we would need either a very big lookup table to get accurate answers, or risk losing accuracy with a "good enough" lookup table.

It's a lot because any sort of human calculation involving so many operations would be monumentally laborious and error inducing, but it's tiny because computers can make these calculations very fast to learn the problem at hand easily.

### Andrej Karpathy: [Intro to Large Language Models](https://www.youtube.com/watch?v=zjkBMFhNj_g)

- Pretraining does: Essentially uses a big data dump of the internet and massive computation power to compress it into a base model which has some understanding of the documents trained on but unlike lossless compression, we're not keeping exact text.

- Finetuning does: Train a base model on a limited quantity of quality documents (around 100K) to get an assistant model. This is where you can make the model respond like a friendly assistant and give it quality labeled data generated by humans (or machines).

- RLHF / preference data does (one sentence, even if fuzzy): This is an extension of fine-tuning where instead of giving it a "best answer" for a given input, we're comparing answers and giving it a preference. Some tasks, like generating a haiku doesn't really have an optimum answer but given preferences/comparison, we can fine tune the model towards a desired goal.

- Inference is: Calculating the next token given a set of input tokens using the parameters. It is usually very fast compared to pre-training or fine-tuning. Each inference pass roughly takes the same amount of time.

- A tool-using model is different from chat because: it can interact with tools which are more suitable for certain tasks (like accurate calculations, up-to-date information available on the internet or syntactically valid code). This allows the model to augment its corpus of knowledge with complementary skills that lead to better answers or capabilities.

- Prompt injection is (one sentence from the later chapter titles is enough): an LLM security issue where malicious actors might hide/disguise prompts to divert the model from its original task. For example, the user might get the model to look-up a webpage where there is a message in white text (not visible to the human eye) asking the model to give some wrong answer.ur
